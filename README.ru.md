# Componenta Filter

Компонуемые предикаты и iterable-фильтры коллекций для PHP 8.4+.

## Установка

```bash
composer require componenta/filter
```

## Требования

- PHP 8.4+
- Расширения PHP `ctype` и `filter`
- `componenta/arrayable`
- `componenta/iterator`

## Контракты

Во второй major-версии разделены проверка отдельного значения и операции над коллекцией.

- `PredicateInterface` содержит только `accept()` и применяется там, где одно значение можно оценить без контекста коллекции.
- `CollectionFilterInterface` описывает обработку коллекции через `getIterator()`, `withIterable()` и `toArray()`.
- `FilterInterface` расширяет оба интерфейса и представляет predicate-backed фильтр коллекции.
- `AbstractCollectionFilter` реализует иммутабельную привязку iterable и `toArray()` для collection-only операторов.
- `AbstractFilter` расширяет `AbstractCollectionFilter` и добавляет predicate-backed итерацию.

## Predicate-backed фильтры

```php
use Componenta\Filter\StringFilter;

$filter = new StringFilter(['one', 2, 'three']);

$filter->accept('value'); // true
$filter->toArray();       // ['one', 'three']
```

Строковые предикаты принимают только `string` и `Stringable`. Числа, логические и другие скалярные значения не приводятся к строке неявно. Предикаты длины считают байты, а не символы Unicode или графемы. Регистронезависимые строковые проверки и проверки расширений используют преобразование регистра ASCII. Преобразование объекта Stringable в строку может выполнять пользовательский код.

## Чистые предикаты и композиция

Пользовательскому предикату больше не требуется iterable-контракт:

```php
use Componenta\Filter\ChainableFilter;
use Componenta\Filter\PredicateInterface;

$positiveInteger = new class implements PredicateInterface {
    public function accept(mixed $value, string|int|null $key = null): bool
    {
        return is_int($value) && $value > 0;
    }
};

$filter = new ChainableFilter($positiveInteger);
$filter->accept(10); // true
```

`Filterable`, `ChainableFilter`, `OneOfFilter`, `NotFilter` и `RecursiveFilter` зависят от `PredicateInterface`. `Filterable` и `ChainableFilter` используют AND-семантику; `OneOfFilter` — OR-семантику, а пустой `OneOfFilter` отклоняет любое значение.

## Collection-only операторы

Следующие операторы намеренно не реализуют `PredicateInterface`:

- `PercentageFilter`: результат зависит от размера коллекции и позиции элемента;
- `UniqueFilter`: уникальность зависит от значений, уже встреченных в текущем обходе;
- `MergingFilter`: объединяет результаты нескольких `CollectionFilterInterface`.

```php
use Componenta\Filter\IntFilter;
use Componenta\Filter\MergingFilter;
use Componenta\Filter\PercentageFilter;
use Componenta\Filter\UniqueFilter;

$filter = new MergingFilter(
    new IntFilter([1, 'two']),
    new PercentageFilter(50, ['a', 'b', 'c', 'd']),
    new UniqueFilter([1, 1, 2]),
);

$filter->toArray(); // [1, 'a', 'b', 1, 2]
```

- `PercentageFilter` оставляет первые floor(количество × процент / 100) элементов по кратчайшему десятичному представлению переданного процента, сохраняющему исходное значение float. Массивы и источники с согласованным Countable не требуется читать полностью; обычный итерируемый источник буферизуется при промежуточном проценте. При 0% источник не читается, при 100% обрабатывается лениво. Для промежуточного процента источник должен быть конечным.
- `UniqueFilter` использует строгое сравнение PHP, сохраняет первое вхождение и независимое состояние каждого обхода. Скалярные значения и идентичность объектов индексируются, сложные значения сравниваются напрямую. Повторные NaN остаются различными, знаковые нули float равны. Потребление памяти растёт с числом уникальных значений.
- `MergingFilter::withIterable()` откладывает открытие агрегатов итераторов и вызов rewind() до первого обхода. Вложенные фильтры используют независимые курсоры общего кеша. Кеш сохраняет прочитанные элементы; длина цепочки агрегатов ограничена 64, превышение вызывает `OverflowException`. При исчерпывающем обходе бесконечного источника объединение не завершится.

По умолчанию `toArray()` возвращает список. При `preserveKeys: true` повторяющиеся ключи массива перезаписываются последующими значениями, числовые строковые ключи преобразуются по правилам PHP, а null-ключ превращается в пустую строку без предупреждения об устаревании. Итераторы сохраняют исходные ключи. При материализации с ключами копируются элементы верхнего уровня; вложенные значения и идентичность объектов сохраняются.

## Точные числовые предикаты

`NumericFilter`, `BetweenFilter`, `RangeFilter`, `GreaterThan*`, `LessThan*`, `MultipleOfFilter` и parity-фильтры не переводят numeric strings в `float` без необходимости.

Поэтому большие целые, длинные десятичные строки и scientific notation сравниваются без потери точности после `2^53`. `NAN` и бесконечности отклоняются value-oriented числовыми предикатами. Значения PHP `float` сохраняют свойственную им двоичную точность; `MultipleOfFilter` использует ограниченную погрешность только для проверяемого значения типа float, если преобразование настроенного делителя в float сохраняет его нормализованное десятичное значение. Числовые строки допускают пробельные символы PHP (пробел, табуляцию, LF, CR, вертикальную табуляцию и перевод страницы). Нулевой байт отклоняется в любой позиции. Автоматического ограничения длины числовой строки нет.

## Диапазоны дат

`DateRangeFilter` принимает `DateTimeInterface` или абсолютные ISO-подобные строки даты/времени. Для локальных строк timezone фиксируется при создании фильтра. Сравнение сохраняет микросекунды. Относительные выражения вроде `tomorrow` и невозможные даты, которые PHP обычно нормализует, не принимаются.

```php
$range = new DateRangeFilter(
    '2026-01-01 00:00:00',
    '2026-12-31 23:59:59',
    timezone: new DateTimeZone('Europe/Copenhagen'),
);
```

## Рекурсивная фильтрация

`RecursiveFilter` обнаруживает циклы итерируемых объектов и ограничивает вложенность коллекций через `maxDepth` (по умолчанию `64`). Независимый параметр `maxAggregateDepth` (по умолчанию `64`) ограничивает последовательное разворачивание `IteratorAggregate::getIterator()` на каждом уровне, включая корневой. Превышение любого ограничения вызывает `OverflowException`. Нулевая глубина коллекций допускает плоский источник в агрегатах; нулевая глубина агрегатов не допускает ни одного агрегата. Циклы объектов вызывают `RuntimeException`.

```php
$filter = new RecursiveFilter($predicate, maxDepth: 32, maxAggregateDepth: 16);
```

## Случайная фильтрация

`RandomFilter` по умолчанию создаёт собственный криптографически стойкий `Random\Randomizer` и не потребляет глобальное состояние `mt_rand()`. Явно переданный генератор — разделяемая зависимость с изменяемым состоянием; `getRandomizer()` возвращает тот же поток случайных чисел, и внешние вызовы продвигают его. Копии конфигурации используют отдельный экземпляр движка, если его копирование поддерживается. Пользовательский движок должен обеспечивать независимость состояния при клонировании или сериализации; внешнее и статическое состояние фильтр изолировать не может. Ошибка копирования движка приводит к `LogicException`. Вероятности 0 и 1 не расходуют случайные числа.

## Проверка конфигурации

Некорректная конфигурация отклоняется заранее через `InvalidArgumentException`, если безопасное выполнение иначе невозможно. Это относится, в частности, к числовым и временным диапазонам, regex, `filter_var()` ID/options, вероятностям, процентам и типизированным спискам строк, классов и ключей.

## Владение состоянием и границы безопасности

Методы `with*` не изменяют конфигурацию исходного экземпляра. Типизированные списки строк и ключей владеют скалярными элементами, произвольные списки конфигурации — элементами верхнего уровня, сохраняя вложенные значения и идентичность объектов. Параметры нативного фильтра копируются на верхнем уровне и на уровне его параметров или массива вызываемого объекта. Итерируемые источники, изменяемые объекты, ресурсы, пользовательские предикаты и состояние вызываемых объектов являются разделяемыми зависимостями, а не глубокими снимками. Одноразовый источник не становится повторно проходимым автоматически, кроме явного оборачивания (как в `MergingFilter`).

Предикаты предназначены для отбора значений, а не для самостоятельной авторизации или очистки данных. Отрицание предиката инвертирует любой false, включая отказ из-за неподдерживаемого типа. Файловые предикаты могут обращаться к зарегистрированным потоковым обёрткам и раскрывать существование путей; отдельно ограничивайте пути, схемы и доступ. Расширение имени не доказывает тип содержимого или его безопасность. Регулярные выражения должны поступать из доверенной конфигурации; учитывайте ограничения ресурсов PCRE. Ошибка сопоставления не считается успешным совпадением. Санитизирующие нативные фильтры не возвращают преобразованное значение через интерфейс предиката и не доказывают его валидность. Нативные отказы отклоняются, в том числе если вместо отказа возвращается настроенное значение `default`. При проверке логического значения корректный false принимается. Нативная функция обратного вызова отклоняет вход только при возврате строго false; null, пустой массив и false внутри возвращённых данных не означают отказ. В режиме массивов независимо проверяется каждый лист входного массива, включая вложенные. Фильтр обходит массивы без записи в ссылки вызывающего кода и без построения преобразованного результата; циклы отклоняются. Общие ациклические подмассивы могут проверяться несколько раз. Сохраняются штатное приведение типов аргументов и обход в глубину. Побочные эффекты самого пользовательского вызываемого объекта или Stringable остаются ответственностью вызывающего кода. Вызываемые объекты, имена классов, инициирующие автозагрузку, Stringable и отражение могут выполнять доверенный пользовательский код. Ограничивайте размеры недоверенных коллекций и строк на уровне приложения.

## Несовместимые изменения относительно 1.x

- `FilterInterface` теперь является пересечением `PredicateInterface` и `CollectionFilterInterface`.
- `PercentageFilter`, `UniqueFilter` и `MergingFilter` являются collection-only и не имеют `accept()`.
- API композиции принимает `PredicateInterface`; пользовательскому предикату больше не нужны iterable-методы.
- `MergingFilter` принимает любые `CollectionFilterInterface` и лениво переигрывает одноразовые источники.
- Строковые предикаты больше не приводят произвольные скаляры к строке.
- Числовые границы принимают `int|float|string` и поддерживают точное decimal/scientific comparison.
- `DateRangeFilter` использует абсолютный детерминированный parsing, зафиксированный timezone и микросекундную точность.
- `RandomFilter` больше не потребляет глобальное состояние `mt_rand()`.
- `RecursiveFilter` ограничивает глубину и обнаруживает циклы.

## Разработка

```bash
composer install
composer test
composer benchmark
```

CI проверяет метаданные Composer, синтаксис исходного кода, тестов и бенчмарков и запускает Pest на PHP 8.4 и 8.5 в обычном, случайном (с фиксированным зерном) и обратном порядке. Быстрая проверка PHPBench выполняется на PHP 8.4; процесс Benchmarks запускает полные измерения на обеих версиях при изменении бенчмарков, проверяемых реализаций нативной и процентной фильтрации или вручную. Сравниваемые ревизии используют одинаковые бенчмарки и зафиксированные версии зависимостей; базовая ревизия настраивается и по умолчанию соответствует основной ветке. Сравнивайте результаты при одинаковой среде, зависимостях, размерах входных данных и сценариях первого и повторных вызовов. Быстрая проверка запуска не является доказательством ускорения. Мутационный аудит проверяет чувствительность тестов и запускается вручную или при изменении его рабочего процесса или регрессионных тестов числовой точности и владения входными данными. Процесс Iterator Integration запускает Pest с зафиксированной ревизией исходного кода componenta/iterator, не меняя опубликованные ограничения зависимостей.
